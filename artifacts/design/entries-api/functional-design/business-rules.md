# Entries API Business Rules

## Request Validation

- Accept JSON object fields name, email, message, case-insensitively as the existing .NET web JSON binder does.
- All three values must be strings and required. Null, missing, empty, or whitespace-only strings fail Required validation.
- name maximum 100 UTF-16 code units; email maximum 200 UTF-16 code units; message maximum 2000 UTF-16 code units. Measure before trimming.
- Email uses behavior equivalent to System.ComponentModel.DataAnnotations.EmailAddressAttribute, not DNS/deliverability validation. Compatibility fixtures are verified against .NET before the implementation is called equivalent.
- Trim accepted strings after validation. Preserve case and internal whitespace.
- Non-object JSON, malformed JSON, wrong field types, and invalid content produce HTTP 400; do not write an entry.
- Ignore unknown fields, including client-supplied id, createdAtUtc, and storage keys. They cannot influence generated values.

## Identity, Time, and Persistence

- id: lowercase hyphenated UUID generated by the server.
- createdAtUtc: server UTC instant serialized in ISO 8601 UTC form. Clients cannot supply it.
- Table keys: fixed partition ENTRIES and sortable ISO-8601 UTC timestamp plus UUID sort key. Conditional put prevents overwrite.
- Writes are durable before returning success. Storage failures do not produce 201.

## Collection Contract

- GET /api/entries returns every entry newest-first by createdAtUtc; ID descending is the deterministic tie-breaker.
- Read uses consistent base-table queries and follows internal pages; no scan, filtering, pagination token, or silent truncation.
- Encoded result over 4 MiB yields sanitized 503 rather than a partial collection. This budget protects the Lambda synchronous response path and constrains the public demo's practical size.
- API responses use JSON and Cache-Control: no-store.

## Errors and Privacy

- 400 response uses a validation-problem shape with `errors` keyed by PascalCase property names, matching the existing API's DataAnnotations member names where applicable. The client already flattens errors or reads title. Preserve useful generic title/details for malformed input.
- 415 for unsupported media type; generic 500 for unexpected failures; sanitized 503 for storage, read deadline, or response-budget failure.
- Never return stack traces, raw AWS errors, request bodies, or stored values. Logs may include request ID, route, operation, status, duration, and sanitized error category only.
- Public unauthenticated access is intentional. Treat all input as synthetic; no confidentiality or abuse-resistance guarantee. Throttling/cost guardrails require explicit Infrastructure Design decision.

## Retry and Ordering

- No automatic POST retry in the browser; no idempotency key exists in the approved API contract.
- POST appends a newly generated entry; subsequent GET order is newest first, consistent with the existing client prepending behavior.
