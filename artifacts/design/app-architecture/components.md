# Components

## React Entry Desk: react-client

- Retain the current component structure and styling; update storage-related wording only as needed.
- Own form state, collection, refresh, saving/loading/error/success feedback, and fetch configuration.
- Interface: same-origin GET/POST /api/entries; consume JSON array/entry and errors/title problem details.

## HTTP Boundary: entries-api

- API Gateway HTTP API, payload format 2.0, exposes exactly GET /api/entries and POST /api/entries.
- get_entries Lambda handles reads; create_entry Lambda handles writes. Both use Python 3.13 and the same shared application/repository code, packaged with each function.
- Lambda adapters translate Gateway events/results; do not put business rules in transport adapters.
- No authentication, individual-entry endpoint, or additional business operation is introduced.

## Entry Application Functions: entries-api

- Coordinate validation, generated UUID/UTC creation timestamp, durable writes, and collection reads.
- Provide a single source of behavior for cloud Lambda adapters and the local development adapter.
- Preserve public JSON field names id, name, email, message, createdAtUtc. Functional design resolves ordering and edge-case validation explicitly.

## Durable Repository: entries-api

- boto3-backed DynamoDB adapter. One table with collectionId string partition key and entryKey string sort key; constant demo partition ENTRIES and timestamp/UUID sort keys.
- Query the base table, not a scan or eventually consistent index; use strongly consistent reads and follow internal DynamoDB pagination.
- Conditional PutItem protects against overwriting a generated key. No JSON-file or in-memory cloud storage.
- One shared partition is intentional for the small demo, not a production throughput design.

## Hosting and Local Development

- CloudFront default behavior serves a private S3 REST origin protected with Origin Access Control.
- CloudFront /api/\* behavior forwards to API Gateway over HTTPS, preserving paths, disabling caching, and allowing POST.
- FastAPI/uvicorn adapter on localhost:5000 calls the same application functions; Vite on localhost:5173 proxies /api to it. Avoid FastAPI's automatic 422 schema-validation path by using the shared request validation.
- DynamoDB Local via Docker supplies persistent local storage, with a named volume and explicit local initialization. Tool availability must be verified in Build.

## Ownership and Scope

entries-api owns application/storage/transport modules and tests; react-client owns UI and client wiring. Release owns Terraform, IAM, resource deployment, and the runbook. No source code or resources have been generated by these documents.
